# 平方麻雀 VRChat ギミック 設計メモ

ブラウザ版(MonakaLabo/baka-mahjong)のルール(ルールブック v0.7)を、VRChat のワールドに置いて遊べるギミックにする。

## 形

- どのワールドにも置ける **プレハブ1つで完結** するギミック。ワールドは別に用意する
- 配布は ALCOM / VCC で追加できるパッケージ(`jp.monakalabo.square-mahjong`)
- ワールド側のプロジェクト設定(レイヤー・タグ・物理)を要求しない。1つのワールドに何卓置いても動く
- スクリプトは名前空間 `MonakaLabo.SquareMahjong` に入れる
- PC 優先。Quest 対応は「できたらやる」
- 演出は控えめ(ブラウザ版のような特大演出はしない)

## 卓

- 8人で囲む八角形の卓。**座る判定(VRCStation)は使わない**。席ごとの「参加」ボタンで担当を決め、立っていても歩いても担当は外れない
- 牌は実寸(幅約26mm)で、卓全体は約2.2m

### 壁牌

- 1回のツモは2枚 = **幢(2枚重ね)1つ** を掴んで持ってくる
- 最初の壁は 1050枚 = **525幢**。**7人の前に 25幢 × 3列(75幢ずつ)**、1人の前は壁なし(卓の決まった1辺)
- 親の最初のツモ1幢は配牌に含めて配り、壁は525幢から始める
- 王牌(ドラ表示牌・ロン牌・嶺上牌)は **卓の中央**
- モデルは「幢」1種類を525個並べる。ツモはその1個を手元へ動かす
- 並び(外から): プレイヤー → 手牌 → 壁 → 中央(王牌)

### 河・手牌

- 河は卓上にすべては出さない(直近の数巡だけ、全部は手元のパッドで見る)。未定
- 自分の手牌は自分の席の前に表向き、他家の手牌は裏向き

## 空間の使い方

- **卓上空のホログラム**: 局・壁牌の残り・供託(リーチ棒)/本場(100点棒)の本数・ドラ表示牌・ロン牌・試合の経過時間・局の経過時間
- **手元のパッド**(ローカル。掴んで持てる): 打牌の操作、全員の河、点数の推移・統計、役一覧、ルール

## 同期の考え方

- 卓ごとに1人(オーナー)が盤面を持ち、他の人は操作をオーナーに送る(ブラウザ版のオンライン対戦のサーバと同じ形)
- VRChat の同期データはインスタンスの全員に届くので、他家の手牌を完全に隠すことはできない(普通のクライアントでは見えない。改造クライアントは規約違反)という前提で作る
- 空席は NPC が打つ

## 進め方

1. 同期の動作確認(TileFlipTest)
2. ルールエンジンを UdonSharp に移植し、ブラウザ版と1手単位で答え合わせ(同じ乱数の種・同じ操作なら同じ結果) … 済(Tests~)
3. 卓と牌を置いて、1人で NPC 7人と打てるようにする
4. 複数人の同期と NPC の代打ち
5. パッド・ホログラム、VR での操作性

## エンジン(SqmEngine)

- ブラウザ版 js/engine の移植。状態はすべて数値の配列(手牌は牌ごとの枚数、副露・河・選択肢は決まった幅の数値の並び)
- 使い方: `SetDefaultRules()` → `NewMatch(seed)` → `pendKind` が `PEND_NONE` なら `Advance()`、それ以外は `BuildLegal(seat)` で選択肢を得て `ApplyAction(act)`
- アクション・選択肢は `OPT` 個の int(`O_TYPE`・`O_SEAT`・`O_MODE`… の位置)
- NPC(ブラウザ版の js/cpu)はまだ移植していない
- Udon は普通の C# よりかなり遅いので、和了判定・待ちの計算が重い場面(打牌ごとのロン判定など)は、実機で測って必要なら数フレームに分ける
